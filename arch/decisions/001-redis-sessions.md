# ADR-001: Общее хранилище сессий Redis

Статус: **Принято**.

## Контекст

Проверка каждого запроса HNS через внутренний ValidateSession в HDS создаёт лишний
сетевой переход и зависимость от доступности HDS. Клиент использует один opaque token.

## Решение

Document-service создаёт и отзывает сессии в Redis. Notification-service проверяет
предъявленный токен непосредственно в Redis при установлении WebSocket-соединения.
Redis — основное хранилище активных сессий; PostgreSQL-копия сессий не требуется.
Не хранить сырой bearer token в серверных постоянных данных или логах; ключ строить по хешу.

## Последствия

Сервисы разделяют версионируемый контракт сессии, но только HDS управляет её жизненным циклом.
При недоступности Redis нельзя считать сессию действительной.
Потеря активных сессий требует повторного входа; восстановление старой копии не должно
возвращать силу уже отозванным сессиям.

## Открыто

- TTL, поля записи, индекс сессий пользователя и механизм массового отзыва.
- Доставка отзыва к уже открытым сокетам, повторная проверка, поведение при разрыве Redis.
- Persistence/HA Redis и гарантии при failover.
- Согласование удаления пользователя в PostgreSQL и прекращения сессий в Redis.

Заменяет PostgreSQL-сессии и HNS → HDS ValidateSession в прежних диаграммах.
