# ADR-004: Вход по логину и паролю

Статус: **Принято**.

## Контекст

Для первой версии выбран вход по логину и паролю. Временный контракт
credentials.method/proof больше не нужен для регистрации и входа.

## Решение

- Логин — username учётной записи, уникальный без учёта регистра. Вход по email
  отдельно не предусмотрен. Пароль сравнивается точно, без trim и смены регистра.
- Register передаёт username, display_name, email и password. Authenticate передаёт
  username и password. Пароль передаётся только по защищённому соединению.
- CLI запрашивает пароль скрытым интерактивным вводом, не аргументом команды.
  Пароль не сохраняется в конфигурации, черновиках или локальной сессии.
- Сервер хранит отдельный солёный хеш пароля, не исходный пароль и не обратимо
  зашифрованную копию. Алгоритм и параметры хеширования фиксируются перед реализацией.
- Неизвестный логин и неверный пароль возвращают одинаковую ошибку unauthenticated
  без раскрытия существования учётной записи. Пароли и токены исключены из логов.
- После успешного входа сервер выдаёт opaque session token; дальнейшие запросы
  используют токен, а не пароль. Хранение сессий в Redis остаётся по ADR-001.

## Последствия

Внешний контракт и внутренний Credentials получают конкретные поля username/password.
Текущий auth <username> остаётся заглушкой до реализации ввода пароля и сетевого клиента.
Выбор способа входа не определяет автоматически протокол повторного подтверждения
личности при удалении аккаунта.

## Открыто

- Политика длины пароля, лимиты ввода и нормализация username.
- Алгоритм/параметры хеширования, защита от перебора и лимиты попыток.
- Подтверждение email при регистрации, восстановление и смена пароля.
- Повторное подтверждение личности для DeleteSelf и срок действия сессии.
