# ADR-002: Kafka для предметных событий, WebSocket для подключения клиентов

Статус: **Принято частично**. Приняты каналы и ответственность; гарантии не согласованы.

## Контекст

Нужны быстрая рассылка изменений активным участникам и будущая поддержка комментариев.
Сохранение персональной записи перед каждой live-отправкой не является обязательным.

## Решение

Document-service публикует предметные события через Kafka. Notification-service
управляет WebSocket-соединениями и доставляет сообщения подходящим получателям.
Разделяем предметное событие, live-сигнал и сохраняемое уведомление.

## Последствия

Одно изменение может иметь много получателей: один исходный event и fan-out на стороне HNS.
Сохранение исходного события и сохранение персональных входящих — разные затраты.
Количество получателей само по себе не доказывает, что outbox является узким местом.
PostgreSQL-нагрузка оценивается по частоте изменений и политике персональных записей.

## Открыто

- Outbox/CDC для надёжной публикации против прямой best-effort отправки после commit.
- Допустимая потеря, повторы и порядок для каждого класса сообщений.
- Какие сообщения сохраняются, зависит ли сохранение от онлайн-статуса.
- Подтверждения клиента, восстановление после reconnect, replay и retention.
- Получатели создания документа: live-обновление пространства против записи во входящих.

Ранее нарисованный outbox остаётся предложением, а не окончательно принятым протоколом.
