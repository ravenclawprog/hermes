# ADR-003: Распространение пользовательских настроек через Redis

Статус: **Предложено**. Требование обновлять все подключения согласовано; протокол ниже — вариант.

## Контекст

Пользователь меняет настройки, имея соединения на нескольких экземплярах HNS.
Загрузка настроек только при WebSocket-подключении оставляет действующие соединения
со старым состоянием. Копирование настроек в каждую сессию усложняет обновление.

## Предлагаемое решение

Document-service владеет пользовательскими настройками и сохраняет их в PostgreSQL.
Redis содержит одну версионируемую запись настроек на пользователя.
После обновления записи HDS публикует `UserSettingsChanged(user_id, version)` через Redis Pub/Sub.
Каждый экземпляр HNS подписан на канал, перечитывает запись и обновляет все свои соединения
этого пользователя. Новое соединение читает актуальное состояние из Redis.

Явный PUBLISH предпочтительнее зависимости от технических Keyspace Notifications.
Сигнал означает необходимость обновления; состояние находится в записи Redis.

## Последствия

Pub/Sub не предоставляет replay. После восстановления подписки HNS перечитывает настройки
подключённых пользователей; периодическая сверка версий компенсирует пропущенные сигналы.
Начальная загрузка и подписка должны исключать окно пропуска обновления.
Устаревшее обновление не должно затирать запись с большей версией.

## Открыто

- Повторяемая синхронизация PostgreSQL → Redis после частичного сбоя (outbox/reconciler).
- Атомарность обновления Redis и публикации сигнала, формат ключа/канала, Redis Cluster.
- Максимальная задержка применения и период сверки версий.
- Поведение при отсутствии записи и недоступности Redis.
- Распространение прав требует отдельного решения: настройки не являются авторизацией.
