# HERMES

**Hermes** — это отказоустойчивая микросервисная платформа для совместной работы с удаленными документами в реальном времени, управляемая через интерактивный CLI-интерфейс. 
Проект проектируется с упором на распределенную архитектуру, асинхронный стриминг событий и готовность к горизонтальному масштабированию в облачной инфраструктуре.

## 🚀 Основной функционал

* **Управление документами (CLI)**: Создание, чтение, удаление и атомарное дополнение документов на удаленном сервере. 
* **Интерактивное редактирование**: Бесшовная интеграция консоли с системными редакторами (по типу `nano` / `vim`) для изменения текста (как, например, реализовано в `git`)
* **Real-time нотификации**: Быстрая доставка уведомлений по протоколу WebSocket (создание/изменение документов, комментарии, упомянания через `@username`) 
* **Оптимистическая блокировка**: Защита от конфилктов при одновременном редактировании одного документа несколькими пользователями

## 🛠 Технологический стек и архитектура

*   **Язык разработки:** Go (Golang) — высокая конкурентность (горутины, каналы) на клиенте и сервере.
*   **Брокер сообщений:** Apache Kafka — асинхронный транспорт для событий совместной работы, обеспечивающий слабую связность микросервисов.
*   **Реляционная БД:** PostgreSQL — строгое ACID-хранилище данных, реализующее паттерн *Transactional Outbox* для гарантированной доставки событий.
*   **In-memory БД:** Redis — маршрутизация WebSocket-сообщений между независимыми подами через *Redis Pub/Sub* и кэширование статусов пользователей.
*   **Оркестрация:** Kubernetes — контейнеризация (Docker) и деплой сервисов с поддержкой авто-масштабирования (HPA).

## 📁 Структура проекта

Проект организован в виде монорепозитория:

```text
├── apps/
│   └── hermes-cli/             # [Client Zone] CLI-приложение на Go (Cobra, Go-каналы)
│       ├── cmd/                # Команды CLI (auth, doc list/create/edit/comment, stream)
│       ├── editor/             # Логика обертки над системными процессами (Vim/Nano)
│       └── client/             # Клиенты для HTTP/gRPC API и WebSocket-соединения
│
├── services/                   # [Server Zone] Бэкенд-сервисы
│   ├── hermes-document-service/# Сервис документов (REST/gRPC)
│   │   ├── internal/
│   │   │   ├── domain/         # Бизнес-модели (Document, Comment, User)
│   │   │   ├── repository/     # Работа с PostgreSQL (ACID-транзакции, миграции)
│   │   │   ├── outbox/         # Transactional Outbox worker (отправка в Kafka)
│   │   │   └── delivery/       # HTTP/gRPC хэндлеры
│   │   └── main.go
│   │
│   └── hermes-notification-service/ # Сервис уведомлений (WebSockets)
│       ├── internal/
│       │   ├── websocket/      # Менеджер WebSocket-сессий (sync.Map для User Status)
│       │   ├── kafka/          # Consumer Group (вычитывание событий из Kafka)
│       │   └── redis/          # Координатор горизонтального Pub/Sub роутинга
│       └── main.go
│
├── deployments/                # Конфигурации для запуска
│   ├── docker-compose.yaml     # Инфраструктура для локальной разработки (PostgreSQL, Kafka, Redis)
│   └── k8s/                    # [Server Zone] Манифесты Kubernetes для деплоя в кластер
│
└── README.md 
```

## 📦 Зависимости проекта

### Инфраструктурные зависимости
*   **Go** (версия 1.22+)
*   **Docker & Docker Compose** (для локального запуска инфраструктуры)
*   **PostgreSQL** (хранение бизнес-сущностей)
*   **Apache Kafka** (режим KRaft — шина событий)
*   **Redis** (Pub/Sub координатор)
