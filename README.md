# HERMES

**Hermes** — микросервисная платформа для совместной работы с удалёнными документами
через консольный клиент. Проект разрабатывается с упором на распределённую архитектуру,
асинхронную доставку событий и горизонтальное масштабирование.

Доступны команды `auth <username>`, `doc list` и `doc read <document_id>`.
CLI обращается к HTTP-серверу `hermes-ds` по адресу из `HERMES_SERVER_URL`.
Локальный режим сервера предоставляет пользователя `demo` и один документ
`example` в его личном пространстве.

## 🚀 Основной функционал

Целевые возможности проекта:

- **Управление документами:** создание, чтение, изменение и удаление документов в рабочих пространствах.
- **Консольный интерфейс:** отдельные CLI-команды и интерактивный терминальный интерфейс (TUI).
- **Интерактивное редактирование:** работа с текстом через системный редактор, например Vim или Nano.
- **Уведомления в реальном времени:** доставка сообщений об изменениях через WebSocket.
- **Оптимистическая блокировка:** проверка версии документа для защиты от конфликтующих изменений.

## 🛠 Технологический стек и архитектура

Текущий CLI написан на **Go** с использованием **Cobra**.
Для серверной части проектируется следующий стек:

- **Go** — серверные приложения.
- **PostgreSQL** — хранение предметных данных.
- **Apache Kafka** — передача предметных событий между сервисами.
- **Redis** — общее хранилище активных сессий; Pub/Sub для обновления настроек рассматривается отдельно.
- **Docker / Kubernetes** — планируемое окружение развёртывания.

Общая схема компонентов: [arch/arch.puml](arch/arch.puml).
Статусы принятых и предлагаемых решений перечислены в [ADR](arch/decisions/README.md).
Гарантии доставки событий и уведомлений пока не согласованы.

## 📦 Зависимости проекта

Для локального запуска:

- **Go** — версии указаны в модулях [CLI](apps/hermes-cli/go.mod) и [сервиса](apps/hermes-ds/go.mod).
- **Task** — опционально, для команд из [Taskfile.yml](apps/hermes-cli/Taskfile.yml).

Для серверного окружения:

- **PostgreSQL** — предметные данные.
- **Apache Kafka** — шина событий.
- **Redis** — активные сессии.
- **Docker & Docker Compose** — опциональный локальный запуск PostgreSQL.

## Локальный запуск

С установленным Task запустите из корня репозитория `task serve`, а во втором
терминале выполните `task smoke`. Введите `local-demo-password` при запросе пароля.
Проверка выведет `Signed in as demo-user`, строку документа `example` и его
Markdown-текст. Сессия проверки хранится во временном каталоге.

По умолчанию задачи берут порт и пароль из `.env.example`. Чтобы изменить
их, скопируйте `.env.example` в `.env` и отредактируйте значения. Обе задачи
используют один порт.

### Запуск без Task

В первом терминале из корня репозитория запустите сервис, задав пароль для
демонстрационного пользователя:

```sh
cd apps/hermes-ds
HERMES_DS_DEMO_PASSWORD='local-demo-password' go run .
```

Во втором терминале из корня репозитория выполните:

```sh
cd apps/hermes-cli
export HERMES_SERVER_URL=http://127.0.0.1:8080
go run . auth demo
go run . doc list
go run . doc read example
```

Введите при входе пароль, указанный при запуске сервиса. Сервис слушает только
`127.0.0.1`. Порт можно задать через `HERMES_DS_PORT`. Сессия действует один час
и сбрасывается при перезапуске сервиса. По умолчанию документ хранится в памяти.

### Локальный запуск с PostgreSQL

Из корня репозитория запустите базу и сервер:

```sh
docker compose up -d --wait postgres
export HERMES_DS_DATABASE_URL='postgres://hermes:hermes-local@127.0.0.1:54329/hermes?sslmode=disable'
task serve
```

Без Task задайте ту же переменную и запустите сервер командой из предыдущего раздела.
Если используется существующая PostgreSQL, укажите её адрес и учётные данные в
`HERMES_DS_DATABASE_URL`. При первом запуске сервис применяет миграцию и добавляет
пользователя `demo`, личное пространство и документ `example`. Для этого
пользователю БД нужны права на создание таблиц в выбранной схеме.

Во втором терминале выполните `task smoke` и введите `local-demo-password`.
Команды CLI одинаковы в обоих режимах. Вход по-прежнему использует
`HERMES_DS_DEMO_PASSWORD`, а сессии хранятся в памяти. После перезапуска сервера
войдите заново, чтобы прочитать тот же документ из PostgreSQL.

Для остановки базы используйте `docker compose down`. Данные сохраняются в
именованном томе. Redis и Kafka относятся к следующим этапам реализации.
